# Map Maker (1.4.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "+" dial → _Make a map_ → region box → options sheet → progress → a georeferenced PDF lands in the Library and activates like any imported GeoPDF.

**Architecture:** Pure page/geo math in `src/core/mapmaker` + a GeoPDF _writer_ in `src/core/geo/geopdf/write.ts` (round-tripped against our own parser). The feature layer stitches the basemap raster through the existing 3D-drape tile fetcher (`fetchBasemapTexture`), draws vectors (contours/tracks/waypoints/margin) with `pdf-lib`, and funnels the result through the existing PDF import path (`storage.importPdf` → `parseGeoPdf` → `addMap`).

**Tech Stack:** pdf-lib (pure JS, OTA-able), UPNG (already a dep), existing dem.ts / contours / terrainAnalysis / libraryStore.

## Global Constraints

- Expo SDK 56, strict TS + `noUncheckedIndexedAccess`, zero-warning lint, prettier width 100.
- `src/core/**` stays pure (no react-native/expo imports); new core files need co-located `*.test.ts` (coverage gate).

- Play submit: local `eas build --local` AAB (JAVA_HOME=openjdk@17, shut down sim/emulator first), bundletool launch check, `eas submit`, verify via Play Developer API, delete artifacts.

### Task 2: `src/core/mapmaker/layout.ts` — page geometry

**Interfaces (produces):**

```ts
export interface PageSpec {
  widthPt: number;
  heightPt: number;
} // A4 = 595.28×841.89, Letter = 612×792
export type PageFormat = 'a4' | 'letter';
export interface MadeMapLayout {
  page: PageSpec; // oriented: landscape iff bbox wider than tall (aspect in projected meters)
  mapRect: { x: number; y: number; w: number; h: number }; // PDF points, origin bottom-left; margin strip at bottom
  drawBbox: BoundingBox; // bbox EXPANDED to the mapRect aspect (center-anchored) — what the raster/vectors cover
  metersPerPt: number;
  approxScaleDenom: number; // e.g. 24000 (rounded to 2 significant digits for the label)
  rasterZoom: number; // web-mercator zoom whose stitched raster covers drawBbox with long edge ≤ 4096 px
  scaleBar: { meters: number; widthPt: number; label: string }; // clean 100 m/250 m/…/5 km ≤ 40% of map width
}
export function layoutMadeMap(bbox: BoundingBox, format: PageFormat): MadeMapLayout;
```

Margins: 24 pt sides/top, 88 pt bottom strip. Meters via WebMercator at the bbox centre latitude (`cos(latMid)` correction).

- [ ] Tests: aspect→orientation; drawBbox contains bbox and matches mapRect aspect (±1e-6); scale round-trips (mapRect width × metersPerPt ≈ drawBbox ground width); rasterZoom obeys the 4096 px cap; scale bar is a clean number ≤ 40% width.
- [ ] Implement; commit `feat(core): made-map page layout math`.

### Task 4: `src/core/geo/geopdf/write.ts` — GeoPDF viewport writer

**Interfaces (produces):**

```ts
/** Attach /VP [ Viewport { BBox, Measure GEO { GPTS (lat-first!), LPTS, GCS /EPSG 4326, BOUNDS } } ] to a pdf-lib page. */
export function attachGeoViewport(
  doc: PDFDocument,
  page: PDFPage,
  mapRect: Rect,
  corners: CornerCoordinates,
): void;
```

GPTS order mirrors the parser (`adobeGeo.ts`): BOUNDS/LPTS `[0 0, 0 1, 1 1, 1 0]` (lower-left, upper-left, upper-right, lower-right in normalized viewport space) with GPTS as matching **lat,lon** pairs. GCS = dict `{ /Type /GEOGCS, /EPSG 4326 }`.

- [ ] Round-trip test (the acceptance test): build a one-page pdf-lib doc, attach a viewport for known corners (use a north-up rectangle: TL/TR/BR/BL of a bbox), save, run **`parseGeoPdf`** on the bytes → expect one georeference whose `viewport.corners` ≈ input (1e-6) and `bbox` ≈ the bbox.
- [ ] Implement with pdf-lib low-level `doc.context` dict/array building; commit `feat(core): GeoPDF viewport writer round-tripped against the parser`.

### Task 5: `src/features/map/mapmaker/composeMapPdf.ts` — composer

**Interfaces:**

- Consumes: Tasks 2–4, `fetchBasemapTexture`/`fetchHeightmap`/`tileRangeForBbox` (dem.ts, terrain.ts), `slopeOverlayRgba`, `contourFeatures`, settings store snapshot.
- Produces:

```ts
export interface MakeMapOptions {
  name: string;
  format: PageFormat;
  basemap: DrapeSource; // 'map' | 'satellite' (relief drape not in dem fetcher; out of scope)
  contours: boolean;
  contourIntervalM: number;
  slope: boolean;
  slopeMinDeg: number;
  slopeMaxDeg: number;
  includeUserData: boolean;
}
export interface ComposeInput {
  bbox: BoundingBox;
  options: MakeMapOptions;
  tracks: { name: string; points: LngLat[] }[];
  waypoints: { index: number; pos: LngLat }[];
}
export async function composeMapPdf(
  input: ComposeInput,
  onProgress: (phase: 'tiles' | 'terrain' | 'compose', frac: number) => void,
): Promise<Uint8Array>;
```

Steps inside: layout → `tileRangeForBbox(drawBbox, rasterZoom)` → `fetchBasemapTexture` → crop raster to drawBbox (pixel offsets from tile-range bbox) → UPNG.encode → `embedPng` full-bleed in mapRect (clip vectors AND images to mapRect via pushOperators clip path) → optional slope PNG (opacity 0.55) from a 256-grid heightmap of drawBbox → optional contours (minor 0.4 pt / major 0.9 pt, brown; label = interval in margin) → tracks (2 pt, category-red) and waypoint circles (5 pt radius, white fill, numbered Helvetica-Bold) → margin strip: title + scale bar + north arrow + `Contours every N m · Made with Inukshuk · <date>` → `attachGeoViewport` → `doc.save()`. Yield (`setTimeout 0`) between phases; check an `AbortSignal`-style cancel flag.

- [ ] Implement; typecheck/lint only (feature layer; correctness rides on Task 4/6 tests + E2E).
- [ ] Commit `feat: made-map PDF composer`.

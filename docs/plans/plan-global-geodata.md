# Global geodata — source-plugin architecture (design package)

> Owner brief, 2026-08-10: _"weather for the whole world and marine charts for
> the whole world… a comprehensive and scalable system, very well-designed…
> The architecture will allow us to pull data from many sources so you can have
> data and stitch everything together very well from all over the globe, not
> just Canada and the U.S."_

Every endpoint, licence and price in this document was probed live on
2026-08-10 unless marked otherwise. The verification log is §8. Where a
"global" claim is impossible for a free app, this document says so instead of
hand-waving — that is the point of §2.4 (radar) and §3.3 (ENC).

---

## 0. Where we actually are (audited, not assumed)

| Domain         | Today                                                                                                                                           | Global?                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Weather drape  | `weatherLayers.ts` → one endpoint const `GEOMET_WMS_ENDPOINT`, 5 hardcoded ECCC layer ids                                                       | GDPS yes / HRDPS+RDPS no               |
| Weather models | `weatherModels.ts` → `WEATHER_MODELS` frozen 3-entry array (hrdps/rdps/gdps), drape+info layer names per variable                               | ECCC only                              |
| Model fallback | `modelCoverage.ts` → 3 hardcoded bboxes + `resolveEffectiveModel()` (selected → GDPS outside domain)                                            | works, ECCC-shaped                     |
| Wind particles | `windCoverage.ts` → `WIND_COVERAGES: Record<WeatherModelId, {speed,dir,gust}>`, WCS 2.0.1 `image/tiff` → `floatTiff.ts` → `windGl.ts`           | GDPS reaches worldwide (verified §8)   |
| Point forecast | `forecast.ts` / `pointReadout.ts` → GeoMet `GetFeatureInfo` + citypage                                                                          | GDPS GFI works worldwide (verified §8) |
| Radar          | `RADAR_1KM_RRAI` / `RSNO` + `RADAR_COVERAGE` bbox + "Canada only" hint                                                                          | **no**                                 |
| Tides          | `tides.ts` → CHS IWLS                                                                                                                           | Canada only                            |
| Bathymetry     | `marineSources.ts` → `MARINE_SOURCES` ladder (nonna → noaa → emodnet → gebco), `sourceCovers()` + `marineSourceLadder()`                        | yes, coarse outside NA/EU              |
| Charts         | NOAA ENC Online `export` + OpenSeaMap seamark XYZ                                                                                               | US + OSM only                          |
| Catalog docs   | `catalog/schema.ts` v1 manifest at `inukshuk.mvxtechnologies.com/catalog/v1/manifest.json`, generated by `scripts/catalog/`, 128 CanTopo sheets | Canada only                            |

**The important structural fact:** the codebase has already invented this
architecture twice, independently and in slightly different shapes.
`marineSourceLadder(view)` is a coverage-filtered priority ladder;
`resolveEffectiveModel(selected, at)` is a coverage-filtered fallback with a
UI-visible "why". They agree on the semantics and disagree on everything else
(one returns a list, one returns a single pick + reason flag; one uses
`GeoBbox`, one uses `CoverageBbox` with identical fields; one is packable-aware,
one isn't). §1 is the union of the two, generalised — **not a new idea, a
promotion of an existing one**.

**The second structural fact: there is no HTTP layer.** Every geodata fetch is a
bare `globalThis.fetch` inside a feature hook — 13 call sites, each with its own
timeout (5 s … 45 s), and each cross-cutting concern implemented approximately
once: retry only in `useWindField`, rate limiting only in `useCompareMatrix`,
the `WEATHER_USER_AGENT` constant living in a _hook_ file while the marine and
catalog fetches send **no User-Agent at all** (met.no 403s exactly that), three
independent module-level LRU `Map`s, and **zero ETag / `If-None-Match` handling
anywhere in `src/`** — which is why the 62 kB catalog manifest is re-downloaded
in full every 24 h. It is also why no weather or marine hook has a single test:
none of them is mockable.

Multiplying the source count by ten on top of that plumbing would multiply the
mess by ten. **M0 in §6 is the shared transport, and it comes first** — not as
tidying, but because per-source rate limits, `requiresUserAgent`, health probes
and the circuit breaker in §1.3 are all transport concerns with nowhere to live
today.

Three duplications the registry absorbs rather than inherits:

- `marineGridUrls` / `marinePointUrl` / `marineRasterUrl` are three separate
  `switch (source.id)` statements. Adding a marine source today means editing
  three functions, not just the array — precisely what the brief wants gone.
- `windFetchBbox`/`needsReanchor`/`windFieldCacheKey` and
  `depthFetchBbox`/`needsDepthReanchor`/`depthChartCacheKey` are the same
  viewport→request-bbox primitive written twice with different constants.
- A weather model is described in **three parallel tables keyed by one id union**
  (`WEATHER_MODELS`, `WIND_COVERAGES`, `MODEL_COVERAGE`) across three files, and
  `resolveEffectiveModel` hardcodes the literal `'gdps'` as the global fallback
  rather than "the first source with empty coverage".

**Constraints that shape every decision below**

- No GRIB2 decoder exists or can economically exist on-device (no `geotiff`
  dep even — `floatTiff.ts` is a hand-rolled single-band float32 TIFF reader,
  uncompressed-only, `SampleFormat === 3`, ≤ 2 Mpx; it cannot read even a
  Deflate-compressed GeoTIFF). Anything GRIB-only needs a server: the hard
  boundary in §2.
- JS-only changes ship by OTA within minutes; a new native dep forces a store
  build. Every client milestone in §6 is OTA-able.
- `src/core/**` must stay pure — lint-enforced by `no-restricted-imports`,
  coverage-gated at branches 70 / functions 80 / lines 80 / statements 80. The
  registry + resolver belong there; the fetchers don't.
- The app is free; cloud sync is the $2.99/mo tier (`plan-profiles-sync.md`).
  Any per-user recurring data cost has to be justified against that.

### 0.1 Commitments from the shipped plans this design must honour

Facts already paid for in blood; contradicting any of them is a regression.

- **Weather is online-only by policy** (`plan-weather-v2.md`) — weather drapes
  never enter offline packs and are hidden under `offlineOnly`. §3.2's offline
  tides are consistent: harmonic constants are a static almanac, not a forecast.
- **GeoMet publishes no U/V wind layers** (0 hits across 8 401 WMS layers), so
  client-side u/v derivation from speed+direction is permanent. Any new
  wind-grid source must declare which convention it serves.
- **WMS `format=image/geotiff` returns `InvalidFormat`** on GeoMet; WCS 2.0.1
  `image/tiff` is the only raw-grid path. Do not re-litigate this.
- **`api.weather.gc.ca` exposes no NWP grids** (104 collections) — it is a
  point-forecast source only.
- **Catalog discovery happens in CI, never on phones** (`plan-map-store.md`):
  "Live APIs … are used **by the generator in CI**, not by phones. Phones only
  hit (a) our manifest, (b) the source's direct file URL — we never rehost."
  §5.5's workflow is deliberately the same shape.
- **`plan-map-store.md` explicitly rejected "NAS endpoint (couples app
  availability to home uptime — avoid for launch)".** §4.1 answers this head-on
  rather than quietly reversing it.
- MapLibre `ImageSource` needs a `file://` URI — **data URIs crash it**. Raster
  sources must declare a real-data `maxzoom` (OSM z19, Esri imagery z17, Esri
  topo z15, the marine raster fallback z12).
- Persisted settings reference **string ids**, and the settings migration ladder
  only compares `typeof`, so every registry-backed setting needs a deep
  `sanitizeX` (the `weatherLayer: null` default already taught this).
- `mapDataCredits.ts` derives the credits roll from `MARINE_SOURCES` so a new
  source can never ship uncredited. §5.4 generalises that guarantee; it must
  not weaken it.
- Total recurring cost of everything shipped so far is **$0**. That is a
  feature, and §7 treats leaving it as a decision rather than a default.

## 1. The provider model

### 1.1 Source descriptor

One declarative record per source. **JSON-expressible on purpose**: that is what
makes "add a country" a data change. It lives in `src/core/sources/`.

```ts
export type SourceDomain =
  | 'weather-raster' // time-dimensioned image drape
  | 'weather-point' // point value / forecast series
  | 'wind-grid' // float32 speed+dir(+gust) grid for the particle engine
  | 'bathy-grid' // float32 depth grid
  | 'chart-raster' // nautical chart imagery
  | 'seamark' // navigational-mark overlay
  | 'catalog-doc'; // downloadable georeferenced document

export type SourceAdapter =
  | 'wms' // OGC WMS 1.3.0 GetMap / GetFeatureInfo
  | 'wmts' // OGC WMTS RESTful
  | 'xyz' // slippy tiles
  | 'wcs' // OGC WCS 2.0.1 GetCoverage → float TIFF
  | 'arcgis-image' // ImageServer exportImage / identify
  | 'arcgis-map' // MapServer export
  | 'rest-json' // templated GET → JSON, with a named response shape
  | 'edr' // OGC API-EDR (CoverageJSON)  [relay-only, see §4]
  | 'file'; // direct file download (catalog docs)

export interface SourceCoverage {
  /** Empty = worldwide. Boxes are generous (EEZ / model-domain scale). */
  boxes: readonly GeoBbox[];
  /** Optional interior box that is trustworthy when `boxes` overstates. */
  conservative?: GeoBbox;
}

export interface SourceTemporal {
  kind: 'past' | 'forecast' | 'static';
  /** Forecast reach from run time, hours. */
  horizonHours?: number;
  /** Nominal frame step, ms (uneven cadences come from capabilities). */
  stepMs?: number;
  /** Model runs per day (0 = continuous/observational). */
  runsPerDay?: number;
  /** Typical minutes between valid time and availability. Drives freshness. */
  latencyMin?: number;
}

export interface SourceLicence {
  /** SPDX-ish label shown verbatim: "CC-BY-4.0", "OGL-Canada-2.0", "CC0-1.0". */
  id: string;
  /** Credit line, shown in Settings → Maps & data and in the on-map pill. */
  attribution: string;
  /** May we serve a cached/derived copy from our own host (relay, packs)? */
  redistribute: 'yes' | 'no' | 'mirror-only';
  /** Is commercial use permitted at this tier? */
  commercial: boolean;
  /** Forces the "Not for navigation" chip. Marine defaults true regardless. */
  notForNavigation: boolean;
  /** Anything a human must read before shipping this source. */
  caveat?: string;
}

export interface SourceLimits {
  /** Sustained requests/second we allow ourselves against this host. */
  rps: number;
  /** Hard daily cap where the provider publishes one, else null. */
  dailyCap: number | null;
  /** Provider demands an identifying User-Agent (met.no does, and 403s без). */
  requiresUserAgent: boolean;
  /** Must not poll while backgrounded (met.no ToS). */
  foregroundOnly?: boolean;
}

export interface GeoSource {
  id: string; // stable, e.g. 'dwd-icon-global'
  domain: SourceDomain;
  adapter: SourceAdapter;
  label: string; // "ICON"  (a11y/Maestro-safe, no regex chars)
  regionLabel: string; // "Worldwide" | "Europe" | "Canada"
  /** Ladder rank within a domain; lower wins before resolution is compared. */
  priority: number;
  endpoint: string;
  /** Per-variable request parameters (WMS layer names, WCS coverage ids…). */
  variables: Partial<Record<SourceVariable, VariableBinding>>;
  coverage: SourceCoverage;
  /** Nominal ground resolution, metres — the quality ordering. */
  resolutionM: number;
  resolutionLabel: string; // "2.5 km" | "~450 m"
  temporal: SourceTemporal;
  auth: 'none' | 'api-key' | 'registered';
  licence: SourceLicence;
  limits: SourceLimits;
  cost: 'free' | 'metered' | 'paid';
  /** A cheap request that proves the source is alive (CI + runtime probe). */
  healthProbe: RequestTemplate;
  /** Reachable without the relay? false ⇒ hidden when the relay is down. */
  direct: boolean;
}
```

`VariableBinding` / `RequestTemplate` carry the only thing that is genuinely
per-source: the URL shape. Templates use a **closed placeholder vocabulary** so
they can be validated statically and rendered by generic adapters:

```
{bbox-epsg-3857} {bbox-4326} {west} {south} {east} {north}
{width} {height} {z} {x} {y} {lat} {lon} {time} {reftime} {layer} {style}
```

**The honest boundary:** a new source that fits an existing adapter (a national
WMS, another ArcGIS ImageServer, one more XYZ tileset) is _pure data_ — a
manifest edit, reviewable as a diff, no code. A source with a genuinely new
protocol (GRIB, EDR/CoverageJSON, S-57) needs a new adapter, which is code.
Adapters are the small, slow-growing set; sources are the large, fast-growing
one. That is the split the brief asks for, stated precisely rather than
promised absolutely.

### 1.2 The registry

Two layers, same discipline as `catalogCache`:

1. **Bundled registry** — a `const` array in `src/core/sources/registry.ts`.
   Ships in the JS bundle, works offline on first launch, OTA-updatable.
2. **Remote overlay** — `https://inukshuk.mvxtechnologies.com/sources/v1/registry.json`,
   fetched on a 24 h TTL with ETag, parsed by `parseSourceRegistry()` which
   **never throws** (bad entries dropped with a warning, wrong `schemaVersion`
   → whole document rejected, bundled registry stands). Overlay entries merge
   by `id`; an overlay entry may disable a bundled source (`enabled: false`)
   but may never introduce a new _adapter_.

That second layer is what makes "add Finland's radar" a Pages commit with **no
app release and no OTA at all**. It is also the kill-switch when a provider
dies at 02:00.

**Hosting conflict to resolve before M5.** `inukshuk.mvxtechnologies.com` is
currently GitHub Pages, deploy-from-branch `main` → `/docs` (there is no Pages
workflow; `docs/CNAME` carries the hostname), and it serves
`DEFAULT_MANIFEST_URL`. `plan-profiles-sync.md` wants that same hostname pointed
at the NAS through a Cloudflare Tunnel. **Both cannot own the apex.** Resolve it
now, cheaply: keep Pages on the apex and give the NAS `sync.` and `relay.`
subdomains. That also keeps the registry and the catalog on infrastructure with
no home-uptime dependency, which is the §0.1 constraint. See D-9.

The manifest has **no signature, hash or integrity check today** — not on the
document, not on downloaded files (the only content gate is a `%PDF` magic
check), and `isHttpUrl` accepts plain `http://`. The registry inherits that
posture. It is acceptable while both live on Pages over TLS; it would not be
acceptable if either moved to a self-hosted origin, which is a second reason to
keep them on Pages.

### 1.3 Resolution rules (deterministic, testable)

`resolveSources(query): GeoSource[]` in `src/core/sources/resolve.ts`. Pure,
no I/O, fully unit-testable — this is the heart of the system.

```
query = { domain, variable, at | viewport, timeMs, offlineOnly, pinnedId? }
```

**Filter** (a source survives only if all hold):

1. `domain` and `variable` are supported.
2. Coverage contains the point / intersects the viewport
   (`conservative` box used when present — RDPS's lesson).
3. `timeMs` falls inside the temporal window (`past` window or run+horizon).
4. `licence.commercial === true` — non-commercial tiers never enter the ladder.
   (This one filter is what keeps Open-Meteo's free tier, Stadia, MapTiler and
   RainViewer out by construction rather than by memory.)
5. Health is not `open` (circuit breaker, §5.3).
6. `direct === true` **or** the relay is configured and reachable.
7. `offlineOnly` ⇒ source has a local pack covering the query.

**Rank** — lexicographic, first difference wins, so it is total and stable:

1. `pinnedId` match (the user chose this model explicitly).
2. `priority` ascending (jurisdictional intent: national > continental > global).
3. `resolutionM` ascending (finer wins).
4. `freshness` — `temporal.latencyMin` ascending, then most recent run.
5. `cost` — `free` < `metered` < `paid`.
6. `id` ascending (deterministic tie-break; makes snapshot tests possible).

**Return the whole ordered ladder, never a single pick.** Consumers walk it and
stop at the first source that actually answers — exactly what
`useMarineChart` already does with `marineSourceLadder`. An HTTP error, an XML
error body where a TIFF was expected, or an all-nodata grid steps to the next
rung silently.

**Degradation chains** are therefore emergent, not hand-written. Worked examples:

| Situation              | Ladder                                              |
| ---------------------- | --------------------------------------------------- |
| Wind drape, Québec     | HRDPS 2.5 km → RDPS 10 km → ICON 13 km → GDPS 15 km |
| Wind drape, Bavaria    | ICON-EU 7 km → ICON global 13 km → GDPS 15 km       |
| Wind drape, Tasman Sea | ICON global → GDPS                                  |
| Radar, Helsinki        | FMI 5 min → OPERA*(relay)* → IMERG global 30 min    |
| Radar, Mumbai          | _(nothing)_ → IMERG global 30 min → satellite IR    |
| Depth, Baie de Gaspé   | NONNA 10 m → NCEI → EMODnet → GEBCO                 |
| Depth, Andaman Sea     | GEBCO                                               |

The last two rows are the honesty test: the ladder must be able to end at
"coarse global" and the UI must **say so**, which is §1.4.

### 1.4 What the UI must always disclose

Non-negotiable, and already half-shipped (`marineSourceCaption`, the AUTO
fallback caption, the "Not for navigation" chip):

- **Active source, named, on screen** — "ICON · 13 km · Worldwide", not just
  "Wind". When the resolver falls back off the user's pinned choice, say why
  ("HRDPS has no data here → ICON").
- **Resolution honestly labelled.** "~450 m" reads very differently from "10 m"
  and the user is entitled to the difference before they trust a contour.
- **Freshness.** "run 6 h ago" already exists for ECCC; generalise it. IMERG's
  ~5.7 h latency must be visible or it will be mistaken for radar.
- **Licence + attribution** reachable in Settings → About → Maps & data, listing
  every source currently rendered _and_ every source baked into a downloaded
  pack (the ledger, §5.4).
- **"Not for navigation"** on every marine surface, always, no exceptions. GEBCO
  and CHS both require it contractually; NOAA requires "not official NOAA ENC"
  on redistributed copies. This chip never turns off for any source.
- **No source may be silently substituted across a licence boundary.** If a
  paid/keyed source is off, the layer degrades or disappears — it never quietly
  swaps to something with different terms.

## 2. Global weather

### 2.1 The direct-from-source global stack (zero server, free, verified)

The single most valuable finding of this research: **two independent free global
models are already reachable by the app's existing WMS/WCS/GetFeatureInfo code
paths.** No relay, no GRIB, no new adapter.

| Source              | Endpoint                        | What we get                                                                                                                | Verified                                                                                         |
| ------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **ECCC GDPS 15 km** | `geo.weather.gc.ca/geomet`      | WMS drape + **WCS float grids worldwide** + GetFeatureInfo worldwide                                                       | §8.1 — WCS over Australia/Africa 200 image/tiff; GFI at Sydney returned 13.89 °C                 |
| **DWD ICON 13 km**  | `maps.dwd.de/geoserver/dwd/wms` | WMS drape `Icon_reg025_fd_sl_{T2M,TOTPREC,UV10M,PMSL}` + GetFeatureInfo, `TIME` PT1H to +180 h, `REFERENCE_TIME` dimension | §8.2 — GetMap 200 over Europe/Canada/Australia; GFI returned 19.88 °C with TIME + REFERENCE_TIME |

DWD's capabilities declare `<Fees>none</Fees>`, licence CC BY 4.0 (attribution
"Deutscher Wetterdienst"), commercial use permitted. Its dimension shape
(`start/end/PT1H` + a `REFERENCE_TIME` default) is **the same shape
`parseTimeDimensionList()` and `parseReferenceTimeDefault()` already parse**,
and its GetFeatureInfo returns a GeoJSON FeatureCollection that
`parseFeatureInfo()` needs one small change to read (the value key is the
variable name, e.g. `Temperature_height_level_above_ground`, not `value`).

That is a second global model — a real _model comparison_ worldwide, which is
the Windy feature the compare matrix was built for — for roughly a day of work.

**Regional high-res, direct, free:**

- ICON-EU on the same GeoServer, but only a thin layer set is published
  (`Icon-eu_reg00625_fd_gl_T`, `_QFF`, `_TOTPREC01H/03H`) — no 10 m wind, so it
  earns a place for temp/precip in Europe and nothing more. Verified §8.2.
- HRDPS 2.5 km / RDPS 10 km stay exactly as they are (North America).
- **AROME (France), UKV (UK), HRRR (US) are NOT directly reachable.** AROME's
  API gateway 401s without a key (§8.5) and its bulk portal is GRIB2; UKV is
  paid-only (Met Office DataHub, £9–£437/mo, free tier is 360 calls/day of land
  _observations_ only); HRRR is GRIB2/Zarr on S3. All three are relay-tier
  features (§4) or nothing.

### 2.2 Point forecasts and the SpotWx-style page

- **Direct, free, worldwide, today:** GeoMet GDPS GetFeatureInfo + DWD ICON
  GetFeatureInfo. Two models, any variable they publish, any lat/lon, no key.
  This alone generalises `forecast.ts` off citypage-Canada.
- **met.no Locationforecast 2.0** — free, CC BY 4.0, commercial use permitted,
  no key, genuinely global, 37 kB of hourly JSON per call (§8.4). Two ToS terms
  are binding and must be encoded in `SourceLimits`: an identifying
  `User-Agent` (generic RN/okhttp agents are blacklisted and 403'd) and
  **20 req/s across all installs of the app combined**, plus "must not retrieve
  new data while the application is not in use". `requiresUserAgent: true`,
  `foregroundOnly: true`, aggressive on-device caching. Good as a
  second opinion and a nice multi-model spread; unsafe as the primary at scale.
- **Open-Meteo** — the best product in the space (30+ models, `best_match`
  auto-selects the highest-resolution model per coordinate, 1–2 km regional to
  9–11 km global, one JSON call). **Free tier is explicitly non-commercial**
  (§8.6, fetched from the pricing page: "Commercial use ❌" on the free column,
  300 000 calls/month, no SLA). Paid tiers grant a commercial licence + a
  `customer-api.open-meteo.com` key: Standard 1 M calls/mo, Professional 5 M,
  Enterprise 50 M+. Exact monthly prices are behind the checkout widget and did
  not render in a plain fetch — **the owner must read the live price before
  committing; the backlog's remembered "~€29/mo" is unverified.** The escape
  hatch is that the _server is AGPLv3 and self-hostable_ and the processed model
  data is republished on AWS Open Data (`s3://openmeteo`), so the relay path and
  the commercial path are the same product at different hosting addresses.
- **SpotWx-style page** = the compare matrix already shipped, widened: rows =
  variables, columns = the resolved ladder at that point. With GDPS + ICON +
  met.no it has three genuinely independent columns worldwide today, and
  HRDPS/RDPS/ICON-EU add regional columns where they exist. This is a UI change
  over an already-general data path, not new plumbing.

### 2.3 Satellite — solved, free, global, no auth

**NASA GIBS** is the answer and it is unambiguous. WMTS, no key, public domain
(soft acknowledgement requested), and it fits the existing XYZ raster path
exactly — the template is a plain slippy URL with a `{time}` segment.

```
https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/{layer}/default/{time}/{tms}/{z}/{y}/{x}.png
```

Verified live (§8.3): `GOES-East_ABI_GeoColor` (TMS `GoogleMapsCompatible_Level7`,
PT10M, latest frame 12:00Z against a 13:11Z probe — ~70 min latency, 154 kB
tile); `Himawari_AHI_Band13_Clean_Infrared` (Level6, PT10M, latest 12:20Z);
`MODIS_Terra_CorrectedReflectance_TrueColor` (daily, Level9);
`IMERG_Precipitation_Rate_30min` (Level6, PT30M, latest 07:30Z ⇒ ~5.7 h latency).

GIBS has **no Meteosat and no live lightning**. For Europe/Africa/Indian Ocean,
**EUMETSAT EUMETView** fills the gap: WMS 1.3.0, capabilities declare
`<Fees>none</Fees><AccessConstraints>none</AccessConstraints>`, no registration.
Verified `msg_fes:rgb_natural` GetMap over Europe → 161 kB PNG (§8.3). Layer set
includes `msg_fes:ir108`, the `msg_iodc:*` Indian Ocean scan, 5-min rapid scan
`msg_rss:*`, and MTG's `mtg_fd:li_afa` Lightning Accumulated Flash Area — the
only free, commercially-clean, real-time lightning layer found anywhere
(Blitzortung explicitly forbids commercial use; GOES GLM has no rendered NRT
tile service).

Verdict: **satellite reaches worldwide, free, with two `xyz`/`wms` descriptors
and zero new code.** This is the cheapest big win in the whole document.

### 2.4 Radar — the honest section

**There is no free, commercially-licensed, worldwide radar. Full stop.**

The option most people reach for is gone: **RainViewer gutted its free tier on
2026-01-01** — nowcast, satellite IR and all colour schemes removed, max zoom
capped at 7, 100 req/IP/min, and the terms are now _personal or educational use
only_ with no published commercial price list (bespoke, via support). Its tiles
still serve (§8.7 — `weather-maps.json` returned 13 past frames, tiles fetched
fine over Québec) which makes it _technically_ trivial and _legally_ unusable.
Do not build on it without a signed, priced licence.

What genuinely is free and commercial-clean:

**OPERA is the sleeper find and the strongest single argument for the relay.**

between "the map is empty in India" and "the map shows something honest".

Realistic reach: clean free radar covers North America + Europe + Japan +
Nordics ≈ **10–12 % of world population**. Everywhere else gets satellite IR +
IMERG. Say this in the UI, not in a footnote.

## 4. The relay tier

### 4.1 What it is, and what it is emphatically not

`inukshuk-relay`: a Docker compose stack on the UGREEN DXP4800 Plus, beside the
PocketBase sync backend from `plan-profiles-sync.md` (same Cloudflare Tunnel,
same B2 backups). **It is an accelerator and a protocol translator. It is never
the only path to any feature.**

The architectural rule, enforced by the `direct` flag on every descriptor and
tested in CI: **for every domain there is at least one `direct: true` source
that is free, licence-clean and global.**

| Domain         | Direct path (no relay)        | What the relay adds                                            |
| -------------- | ----------------------------- | -------------------------------------------------------------- |
| weather-raster | GDPS + ICON global WMS        | ECMWF IFS, GFS, HRRR, AROME drapes                             |
| weather-point  | GDPS/ICON GFI + met.no        | ECMWF/GFS point series, no rate cap                            |
| wind-grid      | **GDPS WCS worldwide**        | ECMWF/GFS/ICON float grids                                     |
| radar          | national free WMS/XYZ + IMERG | **OPERA→tiles (all of Europe)**, DWD, Météo-France             |
| satellite      | GIBS + EUMETView              | edge cache only                                                |
| bathy-grid     | existing 4-rung ladder        | pack pre-building, new national rungs                          |
| chart-raster   | NOAA + GEBCO                  | —                                                              |
| seamark        | OpenSeaMap public tiles       | **our own OSM mirror** (required at scale by ODbL/tile policy) |
| catalog-doc    | direct source URLs            | crawling, HEAD sizing, thumbnails (already how it works)       |
| tides          | IWLS + CO-OPS                 | FES2022 constituent slicing (build-time)                       |

Kill the relay and the app loses model _diversity_ and European radar. It does
not lose weather, wind particles, satellite, bathymetry, charts or tides.

**This is a deliberate, narrow reversal of a prior decision, and it should be
read as one.** `plan-map-store.md` rejected a NAS endpoint because it "couples
app availability to home uptime". That reasoning was correct and still is —
which is why the relay is confined to sources marked `direct: false`, why the
resolver filters those out the moment the relay is unreachable (§1.3, filter 6),
and why §5.3's `sources:check` gate asserts the invariant mechanically: **every
domain must retain at least one `direct: true`, free, licence-clean source.**
A relay outage degrades the model list and blanks the European radar layer. It
can never blank the map, the weather, or the charts. If a future change would
make it able to, CI fails.

### 4.2 Components

1. **GRIB ingest** — `ecmwf-opendata` + Herbie-style `.idx` byte-range fetches.
   The `.idx` sidecar lists `N:offset:date:VAR:LEVEL:type` per field, so one
   `Range:` request pulls a single variable out of a 100 MB+ file. Sources:
   ECMWF IFS/AIFS 0.25° (CC BY 4.0, 15 days, 4 runs/day), NOAA GFS 0.25°
   (public domain, 16 days), HRRR (US 3 km), ICON (CC BY 4.0).
2. **Converters** — (a) float32 GeoTIFF subsets **byte-identical in shape to
   what `floatTiff.ts` already parses**, so wind particles gain models without
   touching the GL code; (b) PNG raster drapes; (c) point JSON.
3. **OPERA → tiles** — EDR `area` query → CoverageJSON → reproject → PNG XYZ.
   Hourly. This is the highest-value single job in the stack.
4. **OpenSeaMap mirror** — Geofabrik extract + the published seamark render
   rules; ODbL-clean and expected by OSM's tile policy at any real volume.
5. **Catalog crawler** — the existing `scripts/catalog/` moved server-side and
   put on a schedule, extended past CanTopo (USGS TNM, IGN, swisstopo, BKG…).
6. **Cache + shield** — filesystem tile cache behind Caddy, per-source rps
   budget, stale-while-revalidate. This is what protects met.no's 20 req/s
   app-wide cap from our own install base.
7. **Registry publisher** — emits `sources/v1/registry.json` with live health,
   which is also what closes the failover loop in §5.3.

### 4.3 Cost and sizing (honest numbers)

- ECMWF IFS 0.25° = 1440 × 721 = 1.04 M points ⇒ **4.2 MB per field** as float32.
  6 variables × 61 steps ≈ 366 fields ≈ **1.5 GB per run**, 4 runs/day = 6 GB/day
  ingested. Keep 2 runs on disk ⇒ ~3 GB. GFS similar. Derived tiles (z0–6) are
  small — tens of MB per run.
- Steady state: **~200 GB disk, ~2 GB RAM, a few hours of CPU/day.** Comfortably
  inside a DXP4800 Plus that is already running PocketBase.
- Marginal cash cost: **≈ $0** (electricity + the existing B2 bucket).
  Bandwidth is the risk if the user base grows — Cloudflare Tunnel caching in
  front, and the direct-source paths absorb overflow by design.
- Effort: **~2–3 weeks** to a useful v1 (ingest + wind grids + OPERA tiles),
  then ongoing babysitting. That is the real cost, and it is a solo owner's
  time, not money.

### 4.4 The commercial alternative, priced

**Open-Meteo paid** is the credible alternative: 30+ models, `best_match`
resolution selection, one JSON call, commercial licence, 99.9 % SLA, EU + NA
servers, and — critically — the _same API syntax_ as the free tier, so the
integration is a hostname + key swap. Tiers: Standard 1 M calls/mo,
Professional 5 M, Enterprise 50 M+. **Prices are behind the checkout widget and
must be read live before deciding** (§8.6). Rough sanity check: 1 M calls/mo
≈ 33 k/day — at 3–5 calls per session that is ~7–10 k sessions/day, far above
current scale, so Standard is almost certainly the right tier if this route wins.

What it does **not** give: map drapes (it is point JSON only — the drape still
comes from GDPS/ICON/relay), radar of any kind, satellite, bathymetry, charts,
tides-as-harmonics. So it is not an alternative to the relay; it is an
alternative to _one part_ of it.

Rejected on terms, not on quality: **Windy API** (€990/yr, and the ToS forbids
using it inside another weather application — a nav app with a weather layer
is exactly that); **meteoblue Maps** (€2 400/yr, good global radar+satellite
composite, but that is 800 sync subscribers' worth of revenue);
**OpenWeatherMap** ($40–600/mo, blended lower-fidelity radar);
**RainViewer** (no published commercial price; see §2.4).

### 4.5 Recommendation — hybrid, in this order

1. **Now, free, no server:** add DWD ICON global (drape + point) and NASA GIBS +
   EUMETView satellite. This alone turns "Canada-only" into "worldwide, two
   models, global satellite" and costs nothing but code.
2. **Next, free, no server:** national free radar descriptors (NOAA nowCOAST,
   FMI, met.no, JMA) + IMERG as the global precipitation fallback.
3. **Then the relay**, scoped tightly to the three jobs nothing else can do:
   OPERA→tiles, ECMWF/GFS wind grids + drapes, OpenSeaMap mirror.
4. **Buy Open-Meteo Standard only if** step 1's two-model spread proves
   insufficient in the field _and_ the owner would rather pay than operate.
   The relay and Open-Meteo are not exclusive; running both is legitimate and
   the registry handles it as two more descriptors.

## 5. Scale and operations

### 5.1 Registry distribution and versioning

`/sources/v1/registry.json` on the existing Pages site, next to `/catalog/v1/`.
Same rules as the catalog manifest, which is already proven in production:
`schemaVersion` gates the whole document, breaking changes bump `/vN/`, the
parser never throws, malformed entries drop individually. Add what the catalog
lacks: a `generatedAt` freshness check, an ETag-conditional fetch, and a
`minAppVersion` per entry so a descriptor needing a new adapter stays invisible
to older clients instead of erroring on them.

### 5.2 Client caching and offline packs

Unify the three existing mechanisms (`marinePacks`, catalog downloads, weather
tile caching) behind one **pack descriptor**: `{ sourceId, bbox, zoomRange |
timeRange, bytes, licenceSnapshot }`. `licenceSnapshot` is the important new
field — a pack outlives the registry entry that created it, and the attribution
ledger has to keep telling the truth about bytes already on disk.

Per-domain caching policy comes off the descriptor, not from scattered
constants: `temporal.latencyMin` sets the tile TTL; `temporal.stepMs` sets the
scrubber's prefetch window; `limits.rps` sets the client-side throttle.

### 5.3 Health and automatic failover

Per-source circuit breaker in a persisted store: `closed → open` after 3
consecutive failures or 3 timeouts, `open` for 10 min, then one half-open probe.
`open` sources are filtered out of the ladder (§1.3 filter 5), so failover is
the resolver doing its normal job — no special-case code path, and it is
unit-testable with a fake clock.

Two layers of monitoring:

- **Runtime:** the breaker, plus a lightweight per-source success-rate counter
  surfaced in Settings → System info (it is already the pattern for the error
  queue).
- **CI:** `npm run sources:check` walks every descriptor's `healthProbe` and
  asserts status + content-type + a minimum byte count (an XML `ServiceException`
  with a 200 status is the failure mode that byte-count catches — the marine
  ladder already learned this). Wire it into `nightly.yml`; a red probe opens an
  issue and, if the owner chooses, flips `enabled: false` in the published
  registry so clients recover before anyone wakes up.

### 5.4 Attribution ledger

`src/core/sources/attribution.ts`: every render and every pack write records
`(sourceId, domain, firstSeen)`. Settings → About → Maps & data renders the
ledger grouped by licence, showing attribution verbatim. This is a licence
obligation for CC-BY sources (GEBCO's credit line is a _requirement_, not a
courtesy), and it is also the only scalable way to keep the About screen honest
as the source count grows past thirty.

### 5.5 Adding a source as a reviewable data change

The workflow the brief asks for:

1. Write a descriptor in `sources/v1/fragments/<id>.json`.
2. `npm run sources:check -- --only <id>` proves it is alive and returns the
   right media type.
3. `npm run sources:snapshot -- --only <id>` renders the ladder for a handful of
   fixture viewports and shows the diff — _this_ is the review artefact, because
   it makes "does adding Finland change what Québec sees?" answerable at a
   glance.
4. PR review reads three things: the licence verdict, the attribution string,
   and the snapshot diff.
5. Merge → the registry rebuilds and publishes → clients pick it up within 24 h,
   with no app release.

Guardrails, enforced in the check script: no descriptor may claim
`commercial: true` without a `licence.id` from an allowlist; no marine
descriptor may set `notForNavigation: false`; no descriptor may reference an
adapter the current `minAppVersion` doesn't have.

## 6. Migration — thin, OTA-able milestones

Each is independently shippable and independently valuable. The stated
"if we stop here" is the honest state of the product at that point.

**M0 — Shared transport.** One `src/data/geoFetch.ts`: per-source rps budget
and burst queue (generalising `burstDelays`), timeout, retry with backoff
(reusing the `errorQueue` 30 s→1 h policy), mandatory User-Agent, ETag /
`If-None-Match` with a persisted validator cache, one LRU replacing the three
module-level `Map`s, and the offline gate that `downloadBytes` already has but
the weather/marine/catalog `fetch` calls bypass. Every existing hook migrates
onto it unchanged in behaviour. _Stop here and: nothing changes for users, but
the weather and marine hooks become mockable and therefore testable for the
first time, the catalog manifest stops re-downloading 62 kB daily, and met.no
becomes legally usable at all._ This milestone is the reason the rest is safe.

**M1 — Extract the registry, change nothing user-visible.** Introduce
`GeoSource` + `resolveSources()` in `src/core/sources/`. Collapse the three parallel weather
tables into one descriptor each, move the three `switch (source.id)` bodies in
`marineSources.ts` into per-entry request templates, unify the twice-written
viewport→bbox primitive, and replace the hardcoded `'gdps'` fallback with "first
source of empty coverage". Make `weatherModelById`/`marineSourceLadder` thin
wrappers over the resolver so no call site changes. Port the existing tests plus
new resolver tests (determinism, tie-breaks, coverage edges, empty ladder,
snapshot ladders for fixture viewports). _Stop here and: nothing changes for
users; the codebase has one ladder instead of two and adding a source stops
being a three-function edit._

**M2 — DWD ICON global.** One descriptor + a small `parseFeatureInfo` widening
for GeoServer's variable-named value key. Model picker grows a worldwide second
model; compare matrix gets a real second column outside Canada; the AUTO
fallback prefers ICON 13 km over GDPS 15 km. _Stop here and: worldwide weather
is real and multi-model — the owner's headline complaint is answered._

**M3 — Satellite.** GIBS (`GOES-East/West`, `Himawari`, `MODIS/VIIRS true
colour`, `IMERG`) + EUMETView MSG as `xyz`/`wms` descriptors, on the existing
raster-drape and time-scrubber machinery. _Stop here and: the map has a global
layer everywhere on earth, including the places with no radar and no charts._

**M4 — Radar, honestly.** Per-country radar descriptors (NOAA nowCOAST, FMI,
met.no, JMA) resolved by viewport, with IMERG as the global fallback and a chip
that names the source and its latency. Retire the blunt "Canada only" hint.
_Stop here and: radar works across North America, the Nordics and Japan; the
rest of the world sees honest satellite precipitation instead of an empty map._

**M5 — Remote registry overlay.** Publish `/sources/v1/registry.json`, add the
fetch + merge + `enabled:false` kill-switch, plus `sources:check` in
`nightly.yml`. _Stop here and: adding a country stops requiring an OTA, and a
dead provider can be disabled from a phone._

**M6 — Marine generalisation.** Move `MARINE_SOURCES` fully onto descriptors,
add AusSeabed/LINZ/national rungs, unify pack descriptors with
`licenceSnapshot`, extend the ledger. _Stop here and: bathymetry is genuinely
worldwide with named per-region quality._

**M7 — Worldwide tides.** FES2022 constituents sliced per region, harmonic
prediction in `src/core/weather/tides.ts`, IWLS/CO-OPS still preferred where
they exist. _Stop here and: tides work anywhere, offline — a capability no
competitor's free tier offers._

**M8 — Relay v1** (the first non-OTA-shaped milestone, but still JS-only on the
client — the relay is a separate repo/container). OPERA→tiles, ECMWF/GFS wind
grids in the existing float-TIFF shape, OpenSeaMap mirror. Descriptors marked
`direct: false` so they vanish cleanly when the relay is unreachable.
_Stop here and: Europe gets real radar and the model list reaches Windy parity._

**M9 — Catalog worldwide.** Crawler extended to USGS TNM, IGN Géoplateforme,
swisstopo, BKG, PDOK, GSI, Geoscience Australia; catalog schema v2 adds
`country` + `licenceId` + WMTS-backed items. _Stop here and: the map store is
worldwide rather than Canadian._

Ordering rationale: M0 is one week of unglamorous plumbing that makes the rest
testable and keeps us inside providers' terms; M2 and M3 then deliver the
owner's actual complaint in the following two shipping cycles, at zero cost and
zero operational burden. Everything requiring money or a server sits behind M7.
M9 also finally automates the catalog crawl, which has been manual since launch
(only two commits have ever touched `docs/catalog/`, so `sizeBytes`/`updatedAt`
drift silently and the "update available" flow cannot fire without a human).

## 7. Owner decisions

**D-1 — Relay vs commercial API vs both.**
_Recommendation: neither, yet — do M2/M3/M4 first (free, no server), then relay
for the three jobs nothing else can do (OPERA, ECMWF/GFS grids, OSM mirror)._
Cost: relay ≈ $0/mo cash, ~2–3 weeks build + ongoing ops. Open-Meteo Standard =
a real monthly bill (price must be read live) but zero ops and instant 30-model
coverage. Both is legitimate. **The decision does not need to be made before M4**,
which is the point of sequencing it this way.

**D-2 — Do we pay for any radar?**
_Recommendation: no._ meteoblue is €2 400/yr (≈ 800 sync subscribers just to
break even), Windy's ToS forbids our use case outright, RainViewer has no
published commercial price. Ship free national radar + IMERG and say what it is.
Revisit only if field feedback says radar-outside-NA is the thing losing users.

**D-3 — What does "worldwide radar" mean in the store listing?**
_Recommendation: "Worldwide satellite precipitation; live radar in North
America, Europe and Japan."_ Overclaiming here is the fastest route to
one-star reviews.

**D-4 — Navigation-grade charts.**
_Recommendation: never, for the free app._ Only NOAA is free (CC0). CHS, UKHO,
AHO, Norway are all paid or membership-gated, and no free global ENC exchange
set exists. Keep the "Not for navigation" chip permanent. If the owner wants
real charts, the only route is a paid distributor deal (the GeoGarage thread
already in the backlog), and that is a business decision, not an architecture one.

**D-5 — met.no as a point source?**
_Recommendation: yes, but as a second opinion only._ Free, CC BY 4.0, global,
no key — but 20 req/s across **all installs combined** and a no-background-polling
clause. Encode both in `SourceLimits`; never make it the primary.

**D-6 — Registry overlay: ship it, or stay bundled-only?**
_Recommendation: ship it at M5._ It is ~150 lines reusing the catalog parser
pattern, and it converts every future source addition from an OTA into a commit.
It also gives a remote kill-switch, which is worth it on its own.

**D-7 — OpenSeaMap mirror.**
_Recommendation: yes, when the relay exists._ ODbL permits it and OSM's tile
policy effectively requires it at any real volume. Until then the public tiles
are fine and we are small.

**D-8 — Open-Meteo free tier for a "beta" period?**
_Recommendation: no._ Their terms say commercial use ❌ on the free tier, and a
free app with a paid sync tier is commercial. Using it and hoping is exactly the
kind of thing this document exists to avoid.

**D-9 — Who owns `inukshuk.mvxtechnologies.com`?** _(needs an answer soonest —
it blocks sync M1, not just this plan)_
_Recommendation: Pages keeps the apex; the NAS gets `sync.` and `relay.`
subdomains._ The catalog manifest already lives on the apex and the sources
registry will join it; both must stay on infrastructure with no home-uptime
dependency, per §0.1. `plan-profiles-sync.md` assumes the apex points at the
NAS — **that assumption needs correcting before sync M1 ships**, or the map
store breaks the day the Tunnel goes up. Five minutes of DNS thinking now, or a
production outage discovered by a user later.
